# 需求分析

## 1. 项目背景

校园场景下，学生和教师有稳定的点餐需求，商家需要便捷的接单与履约流程，管理员需要查看全局订单与运营概况。课程设计目标是在本地环境实现一个可运行、可演示、可分析的校园外卖管理系统。

## 2. 系统目标

1. 完成从登录到下单、支付、履约、评价的业务闭环。
2. 基于 MySQL 实现规范化的关系模型与约束控制。
3. 通过后端事务保障下单与库存更新的一致性。
4. 提供前端最小演示页面，便于课堂演示和答辩。
5. 提供 C++ 辅助工具支持测试数据生成和销售数据分析。

## 3. 用户角色

### 3.1 学生

1. 登录系统。
2. 浏览店铺和菜品。
3. 管理购物车。
4. 创建订单并模拟支付。
5. 对已完成订单进行评价。

### 3.2 教师

功能与学生一致，使用 TEACHER 角色访问同类用户端接口。

### 3.3 商家

1. 维护店铺信息。
2. 管理菜品分类和菜品。
3. 菜品上架和下架。
4. 处理订单状态流转。

### 3.4 管理员

1. 查看全局订单列表与详情。
2. 查看统计信息（订单总数、已完成数量、总销售额、待处理数量）。

## 4. 功能需求

1. 登录注册：支持账号登录和角色识别。
2. 店铺浏览：用户可查看店铺列表及基础信息。
3. 菜品浏览：用户可按店铺查看菜品。
4. 购物车：用户可加入、查看、修改、删除购物车项。
5. 下单：从购物车创建订单并生成订单明细。
6. 支付模拟：订单由待支付进入已支付状态。
7. 商家订单处理：按 PAID -> ACCEPTED -> PREPARING -> DELIVERING -> COMPLETED 流转。
8. 评价：用户对已完成订单进行评分与评论。
9. 管理员查看订单和统计：管理员拥有全局可见性。

## 5. 非功能需求

1. 数据一致性：下单、取消等关键流程必须事务化处理。
2. 权限控制：基于 JWT 和角色中间件限制接口访问。
3. 可扩展性：采用分层结构，便于扩展统计、导出、推荐等功能。
4. 本地可运行：无需 Docker，使用 MySQL + Go + Vue + C++ 即可运行。
5. 课程演示友好：前端支持详情弹层、状态时间线与统计卡片，便于答辩展示。
